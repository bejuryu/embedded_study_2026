# 001. 하드웨어 기본 설명

## 1. 개요 및 배경

ESP32-P4는 Espressif에서 2024년 양산을 시작한 고성능 애플리케이션 프로세서(AP)임.
주요 특징은 기존 ESP32 시리즈에 포함되었던 무선 통신(Wi-Fi/Bluetooth) 기능을 제외하고, 연산 성능, 멀티미디어(오디오/비디오) 처리 및 하드웨어 가속 기능에 특화되었다는 점임. 이를 통해 외부 무선 통신 칩(예: ESP32-C6)과 결합하여 고성능 듀얼 칩 솔루션을 구성할 수 있음.

## 2. 기존 ESP32 시리즈와의 주요 차이점 비교

| 구분                           | 일반 ESP32 / ESP32-S3      | ESP32-P4                         | 주요 특징 및 변경 사항                                                                                                                     |
| :----------------------------- | :------------------------- | :------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| **아키텍처 (코어)**            | Xtensa 듀얼 (최대 240MHz)  | **RISC-V 듀얼 (HP) + 싱글 (LP)** | **고성능 코어(400MHz, HP 2개)**와 **저전력 코어(40MHz, LP 1개)**로 구성된 하이브리드 아키텍처 적용                                         |
| **동작 클럭**                  | 최대 240 MHz               | HP: **400 MHz**, LP: 40 MHz      | 연산 처리 및 디스플레이 갱신 성능 향상                                                                                                     |
| **무선 통신 (Wi-Fi/BT)**       | 내장 (온보드 안테나)       | **미지원 (외부 모듈 필요)**      | 자체 통신 기능이 없으므로 ESP32-C6 등의 **보조 무선 통신 칩과 SDIO/SPI (ESP-Hosted 프레임워크 기반) 인터페이스**를 통한 네트워크 구성 필요 |
| **메모리 (SRAM)**              | 320KB ~ 512KB              | **HP 768KB + LP 32KB**           | 내부 메모리 대역폭이 확장되었으며, 16MB~32MB 용량의 고속 PSRAM 인터페이스 지원                                                             |
| **디스플레이 인터페이스**      | RGB / I80 / SPI            | **MIPI-DSI**                     | 고속 시리얼 인터페이스인 MIPI-DSI를 지원하여 **720p 해상도 기준 60Hz 렌더링** 가능                                                         |
| **카메라 인터페이스**          | DVP (병렬 인터페이스)      | **MIPI-CSI**                     | 대역폭이 넓은 MIPI-CSI를 지원하여 **200만 화소(1080p 이상) 해상도의 영상 실시간 처리** 가능                                                |
| **하드웨어 가속 (멀티미디어)** | -                          | **H.264 인코더, JPEG, PPA, ISP** | 영상 압축(H.264), 2D 그래픽 처리(PPA), 이미지 프로세싱(ISP)을 전용 하드웨어 가속기로 오프로드하여 CPU 부하 감소                            |
| **USB 인터페이스**             | Full-Speed (12Mbps, S2/S3) | **High-Speed OTG (480Mbps)**     | High-Speed 대역폭을 지원하여 대용량 저장장치 및 고해상도 웹캠 연결 용이                                                                    |
| **보안 기능**                  | 기본 암호화 가속 (AES/RSA) | **독립형 하드웨어 보안 엔진**    | Secure Boot V2 및 하드웨어 기반 암호화 가속 (AES/SHA/RSA/ECC) 지원을 통해 IoT 기기 및 OTA 환경의 보안성 강화                               |

## 3. M5Stack TAB5 하드웨어 구성

M5Stack TAB5 디바이스는 ESP32-P4 메인 프로세서와 함께 다음과 같은 외부 주변장치를 내장하여 종합적인 하드웨어 테스트 환경을 제공함.

- **네트워크**: ESP32-C6 보조 칩 탑재 (Wi-Fi 6 및 Bluetooth 통신 지원)
- **디스플레이 및 카메라**: 5인치 1280x720 IPS 터치스크린 (MIPI-DSI) 및 SC2356 2MP 카메라 (MIPI-CSI)
- **오디오 시스템**: ES8388 (오디오 코덱 및 스피커 출력), ES7210 (AEC 에코캔슬링 지원 듀얼 마이크 버퍼)
- **인터페이스 확장**: USB 2.0 (Type-C OTG, Type-A Host), RS-485 터미널 (SIT3088), HY2.0-4P (I2C/GPIO) 외부 확장 포트, MicroSD 슬롯
- **센서 및 전력 관리**:
  - BMI270 (저전력 6축 모션 센서), RX8130CE (하드웨어 RTC)
  - INA226 (배터리 모니터링 IC), NP-F550 규격 교체형 배터리 인터페이스 지원

## 4. FreeRTOS 운영체제의 이해 및 타 환경 비교

ESP-IDF는 **FreeRTOS** 커널을 기본으로 탑재하고 있으며, ESP32-P4의 듀얼 코어(SMP) 환경을 효율적으로 제어하기 위해 해당 OS 아키텍처에 대한 이해가 필수적임.

### 4.1. 베어메탈(Bare-metal) 및 FreeRTOS 비교

| 구분          | 베어메탈 (No OS)                                                                                            | FreeRTOS                                                                                                                   |
| :------------ | :---------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| **운영 방식** | 무한 루프(`while(1)`) 내에서 센서 측정, 출력, 통신 등의 작업을 순차적으로 실행함                            | 스케줄러(Scheduler)를 통해 할당된 시간(Tick) 단위로 다수의 작업(Task)을 전환하며 실행함 (멀티태스킹)                       |
| **장점**      | 구조가 단순하고 부팅 오버헤드가 최소화됨. 하드웨어 자원의 직접적인 제어 및 독점 가능                        | 블로킹(Blocking) 동작 시 다른 태스크로 전환이 가능하여 시스템 지연 방지. 멀티코어 환경에서의 작업 분할 및 관리가 용이함    |
| **단점**      | 병렬 처리 시 타이머 및 인터럽트 구조가 복잡해지며, 특정 작업의 지연이 전체 시스템의 블로킹을 유발할 수 있음 | 커널 운영을 위한 메모리(RAM) 및 CPU 오버헤드 발생. 뮤텍스(Mutex), 세마포어(Semaphore) 등 동기화 처리를 위한 추가 구현 필요 |

### 4.2. FreeRTOS 및 타 RTOS (Zephyr 등) 비교

| 구분            | FreeRTOS (Amazon 지원)                                                                                    | Zephyr OS (Linux Foundation 주도)                                                                                    |
| :-------------- | :-------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------- |
| **구조적 특징** | 태스크 스케줄링 중심의 **경량 커널** 구조 제공                                                            | 디바이스 트리(Device Tree) 및 다양한 미들웨어를 포함하는 **통합형 RTOS** 아키텍처                                    |
| **장점**        | 높은 시장 점유율로 인한 다양한 레퍼런스 확보. 커널 메모리 점유율이 낮아 리소스가 제한적인 MCU에 적용 용이 | 하드웨어 추상화(HAL)를 통한 코드 재사용성 우수. 자체 네트워크 스택 및 다양한 통신 프로토콜 내장                      |
| **단점**        | 파일시스템 및 무선 통신(Wi-Fi 등) 미들웨어를 칩 제조사(Vendor) 제공 라이브러리(예: ESP-IDF)에 의존해야 함 | 초기 학습 곡선이 높음. Kconfig 및 CMake 기반의 복잡한 빌드 시스템 요구. 소형 센서 제어용으로는 시스템 규모가 큰 편임 |
